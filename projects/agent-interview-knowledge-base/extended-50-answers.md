# AI Agent 岗位扩展 50 题个人答案卡

这份题库按面试阶段组织。每题都包含“参考回答、项目证据、追问方向、容易踩坑”。参考回答是你的回答骨架，正式面试前要用自己的口语再练一遍。

## 初试：项目匹配与基础判断（1-15）

### 1. 你为什么从 Java 后端转向 Agent 开发？

- **参考回答**：我没有放弃 Java 后端，而是把多年 To B 系统经验用于 AI 应用落地。Agent 真正难的是业务建模、权限、数据、失败恢复和交付，这些正好是我原来的强项。
- **项目证据**：12 年研发经验、9 年 Java 后端及架构经验；排产 Agent、面料检索、Protocol AI 和 BugleCat。
- **追问方向**：Java 经验如何帮助 Agent 项目？为什么不用纯算法路线？
- **容易踩坑**：说成“完全转行”；只讲模型和框架，不讲业务交付。

### 2. 你做过最完整的 Agent 项目是什么？

- **参考回答**：最完整的是制造业排产 Agent，覆盖真实业务问题、意图识别、SQL 和规则路由、LangGraph 编排、权限、dry-run、执行校验、评测和 E2E。
- **项目证据**：49,981 条订单、20 类意图、约 80% 请求无需 LLM、约 95% 离线意图准确率。
- **追问方向**：你个人负责哪一段？哪些是团队共同完成？
- **容易踩坑**：把所有模块都说成自己独立完成；把 LLM 描述成直接控制生产数据。

### 3. 你理解的 Agent 和普通聊天机器人有什么区别？

- **参考回答**：聊天机器人主要生成文本，Agent 还要理解任务、选择工具、维护状态、处理结果和失败，并受到权限和业务规则约束。
- **项目证据**：排产 Agent 有状态图、工具路由、执行校验；BugleCat 有 Tool Calling、MCP、恢复和审批。
- **追问方向**：什么场景不适合 Agent？
- **容易踩坑**：把“能调用 API”就等同于完整 Agent。

### 4. 你如何判断一个需求是否值得做成 Agent？

- **参考回答**：先看任务是否需要自然语言理解、动态路由、多步工具调用或解释；步骤固定且结果强确定的部分优先普通服务或工作流。
- **项目证据**：排产项目采用 SQL、规则优先，Agent 只处理需要理解和编排的部分。
- **追问方向**：如果业务方坚持要 Agent，你怎么沟通？
- **容易踩坑**：为了体现 AI 而强行引入 LLM。

### 5. 你的 AI 项目中，个人贡献如何证明？

- **参考回答**：按我负责的设计、代码、评测和交付证据说明，不把团队结果全部归为个人。每个项目都能说清我做的模块、做出的决策和验证方式。
- **项目证据**：排产 Agent 技术负责人；面料项目负责人；Protocol AI RAG 框架优化；BugleCat 独立开发。
- **追问方向**：给一个你亲自改过的模块或问题。
- **容易踩坑**：使用“全面负责”“独立完成全部系统”等无法举证的表述。

### 6. 你如何向业务人员解释 Agent 的边界？

- **参考回答**：把 Agent 定位为理解和辅助决策层，核心规则和写操作由系统控制；通过预览、确认、回读和审计让业务人员知道它做了什么。
- **项目证据**：排产 Agent 的 governance、preview/dry-run、execute、verify 链路。
- **追问方向**：业务人员不信任模型怎么办？
- **容易踩坑**：承诺模型“不会出错”。

### 7. 你的项目中哪些能力是真实落地，哪些是预研？

- **参考回答**：排产 Agent 和面料检索是公司真实业务项目；Protocol AI 是 2026-08-07 至 2026-09-04 的 RAG 框架优化和技术预研，未上线生产；BugleCat 是个人开源项目。
- **项目证据**：四个项目的公司、时间和状态已在知识库事实卡中记录。
- **追问方向**：为什么 Protocol AI 没有上线？你如何评价结果？
- **容易踩坑**：把“平台目标是医疗”说成“医疗生产已上线”。

### 8. 你如何保证简历中的技术和指标真实？

- **参考回答**：每条表述都绑定项目、时间、角色和证据；无法确认的指标标记待核验，面试时不现场补数字。
- **项目证据**：知识库中的事实红线和证据补充清单。
- **追问方向**：如果面试官质疑 95% 或 80%，怎么回答？
- **容易踩坑**：为了匹配 JD 临时增加技术或效果。

### 9. 你如何做一次 Agent 需求分析？

- **参考回答**：先明确用户、业务动作、输入输出和验收，再拆意图、工具、数据、权限、异常和评测样本，最后决定哪些节点需要模型。
- **项目证据**：排产项目把订单、机台、规格和排产诊断拆成 20 类意图。
- **追问方向**：需求不清时你先做什么？
- **容易踩坑**：一上来就选模型或框架。

### 10. 你如何处理一个回答错误的 Agent？

- **参考回答**：先保留请求、路由、工具参数、检索结果和模型输出，判断是意图、数据、工具、Prompt 还是模型问题，再用最小修复和回归样本验证。
- **项目证据**：Langfuse、Golden Cases、回读校验和 Playwright E2E。
- **追问方向**：如何区分模型错和业务规则错？
- **容易踩坑**：只根据最终文本猜原因。

### 11. 你最熟悉的 Agent 技术栈是什么？

- **参考回答**：业务 Agent 侧熟悉 Python、LangGraph、SQL、Qdrant、Langfuse；RAG 侧使用 Qwen Embedding、pgvector；个人 Coding Agent 使用 Rust、Tauri/Svelte、MCP。
- **项目证据**：排产、Protocol AI、BugleCat 技术栈。
- **追问方向**：为什么不同项目选不同语言？
- **容易踩坑**：把接触过的框架都说成生产级熟练。

### 12. 你如何看待 AI 编程工具？

- **参考回答**：AI 适合加速方案草拟、代码生成、测试和排障，但边界、数据、安全和验收仍由人负责；我会通过 Review、测试和运行证据确认结果。
- **项目证据**：长期使用 Docker、Jenkins，并使用 AI 辅助配置和开发；BugleCat 本身研究 Coding Agent。
- **追问方向**：AI 生成错误代码如何处理？
- **容易踩坑**：说成“AI 写完就能直接上线”。

### 13. 你做过哪些评测？

- **参考回答**：按任务拆分离线意图准确率、检索 badcase、Golden Cases、LLM-as-judge、人工复核和 Playwright E2E；不同指标验证不同层次。
- **项目证据**：排产 Agent 约 95% 意图准确率、30 条 Golden Cases；面料项目真实 badcase；Protocol AI 证据追溯。
- **追问方向**：LLM-as-judge 为什么不能单独作为结论？
- **容易踩坑**：只给一个“准确率”覆盖所有质量。

### 14. 你如何做 Agent 的成本控制？

- **参考回答**：先用规则、SQL、缓存处理确定性请求，减少不必要的模型调用；控制检索范围和上下文预算，重复任务采用缓存和批量处理。
- **项目证据**：排产约 80% 请求无需 LLM；面料项目 Redis 缓存、批量查询和异步索引。
- **追问方向**：成本和准确率冲突时如何取舍？
- **容易踩坑**：只谈模型单价，不谈调用次数和上下文长度。

### 15. 你如何评价一个 AI 项目是否成功？

- **参考回答**：同时看业务结果、任务质量、稳定性、成本、可观测性和用户是否愿意使用；预研项目还要看方法是否可验证和能否迁移。
- **项目证据**：排产的业务落地和评测；Protocol AI 的框架优化和证据边界。
- **追问方向**：没有线上指标的预研怎么证明价值？
- **容易踩坑**：用 Demo 效果代替生产价值。

## 复试：技术深挖与系统设计（16-35）

### 16. 如何设计 Agent 的状态机？

- **参考回答**：把输入、意图、工具计划、工具结果、人工确认和最终结果作为显式状态；每次转换有前置条件、超时和失败路径，不能只依赖对话文本。
- **项目证据**：排产使用 LangGraph StateGraph；BugleCat 有持久化会话和恢复。
- **追问方向**：状态如何持久化？如何避免重复执行？
- **容易踩坑**：把状态机理解成 Prompt 中的一段文字。

### 17. Tool Calling 的 schema 如何设计？

- **参考回答**：工具名称、用途、输入类型、必填项、枚举范围、权限要求和错误码都要明确；工具返回结构化结果，避免把自然语言当接口协议。
- **项目证据**：BugleCat 的 ToolRegistry；排产工具需要参数校验和状态约束。
- **追问方向**：如何兼容工具版本变化？
- **容易踩坑**：工具参数过于宽泛，模型可以自由拼接 SQL 或命令。

### 18. 如何防止 Prompt Injection？

- **参考回答**：把系统指令、用户内容、检索内容和工具结果分层；对外部内容按不可信数据处理，工具权限独立校验，敏感操作必须人工确认和审计。
- **项目证据**：排产的权限、治理和 dry-run；BugleCat 的 Sandbox + Approval。
- **追问方向**：如果攻击内容藏在知识库文档里怎么办？
- **容易踩坑**：认为加一句“不要被注入”就足够。

### 19. 如何限制 Agent 的数据访问范围？

- **参考回答**：在身份、角色、资源范围和工具层同时校验，查询条件由服务端生成或绑定，不能相信模型传入的用户 ID；结果也要做数据范围过滤。
- **项目证据**：排产四级权限；Noval Auth 的“身份 → 有效角色 → 权限点 → 资源范围”路径；面料 RBAC。
- **追问方向**：页面权限和 API 权限如何避免不一致？
- **容易踩坑**：只做前端按钮隐藏。

### 20. Hybrid Search、Composite Search 和 GraphRAG 如何选择？

- **参考回答**：关键词适合精确术语，向量适合语义相似，属性过滤适合业务约束，图检索适合关系路径；根据问题类型路由或组合，不把所有问题强行塞进 GraphRAG。
- **项目证据**：Protocol AI 章节检索和关键词兜底；排产的 SQL 优先与 Hybrid/Composite/GraphRAG 路由；面料向量加属性。
- **追问方向**：如何判断哪种检索更好？
- **容易踩坑**：把 GraphRAG 当成比向量检索更高级的必选方案。

### 21. 文档切片如何确定粒度？

- **参考回答**：按文档结构、章节语义和回答所需上下文确定；过大影响召回精度和上下文预算，过小会丢失条件和结论，因此要结合章节主题词、重叠和实际 badcase 调整。
- **项目证据**：Protocol AI 采用章节级检索、主题词增强和上下文预算控制。
- **追问方向**：表格、标题和引用如何处理？
- **容易踩坑**：只按固定 token 长度机械切片。

### 22. 如何评估 Embedding 模型？

- **参考回答**：先构造带正负样本的真实查询集，分别测召回、排序、属性一致性、延迟和资源成本，再结合人工复核决定；不能只看模型参数规模。
- **项目证据**：面料项目使用真实 badcase 验证 Qwen3-VL-Embedding-8B；Protocol AI 使用 Qwen Embedding。
- **追问方向**：没有标注数据时怎么办？
- **容易踩坑**：把模型名称当成效果证据。

### 23. 如何处理上下文超长和上下文污染？

- **参考回答**：限制检索数量和 token 预算，按章节和来源去重，优先高置信证据；多轮对话分离任务状态、用户输入和历史记忆，避免无关内容进入当前任务。
- **项目证据**：Protocol AI 的上下文预算和章节级来源追溯；BugleCat 的上下文压缩。
- **追问方向**：压缩后如何避免丢关键约束？
- **容易踩坑**：简单截断对话历史。

### 24. Agent 如何处理超时、重试和幂等？

- **参考回答**：每个工具定义超时和可重试类型，网络失败可以有限重试，业务拒绝不能盲目重试；写操作必须使用幂等键和执行状态，重试前确认是否已经产生副作用。
- **项目证据**：排产幂等、回读校验；面料异步索引重试；BugleCat 预算与超时。
- **追问方向**：第三方接口超时但实际已成功怎么办？
- **容易踩坑**：所有异常都自动重试。

### 25. 如何设计 Agent 日志和 Trace？

- **参考回答**：记录请求 ID、会话 ID、路由、模型版本、工具名、参数摘要、耗时、结果状态和人工确认；敏感内容脱敏，Trace 能串起一次完整任务。
- **项目证据**：Langfuse、JSONL 审计、来源追溯和操作日志。
- **追问方向**：如何控制日志成本和隐私？
- **容易踩坑**：把完整敏感 Prompt 和业务数据原文全部写日志。

### 26. RAG 结果如何防止模型臆造？

- **参考回答**：要求回答绑定检索证据，保留来源和章节，证据不足时明确说无法确认；对高风险内容设置人工复核和拒答边界。
- **项目证据**：Protocol AI 的来源角色、引用追溯和证据边界。
- **追问方向**：引用存在但内容不支持结论怎么办？
- **容易踩坑**：只在 Prompt 里写“不要幻觉”。

### 27. 多 Agent 什么时候值得使用？

- **参考回答**：当任务确实需要不同角色、并行处理和互相审查时才使用；单 Agent 或确定性流程能解决时，多 Agent 只会增加通信、成本和调试复杂度。
- **项目证据**：个人 campaign-muti-agent 有 Coordinator、Executor、Retriever、Reviewer 和 ROI 路由；排产项目优先确定性链路。
- **追问方向**：多 Agent 如何共享状态和预算？
- **容易踩坑**：用角色数量展示复杂度，却没有业务收益。

### 28. 模型供应商切换要抽象哪些边界？

- **参考回答**：抽象模型调用接口、消息格式、工具协议、Embedding、流式事件、错误和计费信息；业务状态机不应绑定某个供应商 SDK。
- **项目证据**：BugleCat 支持 OpenAI-Compatible；个人预研使用 Provider Adapter。
- **追问方向**：如何处理不同模型的能力差异？
- **容易踩坑**：只替换 API 地址，忽略结构化输出和工具调用差异。

### 29. 如何做回归测试和版本发布？

- **参考回答**：变更前固定 Golden Cases，变更后跑路由、检索、工具、权限和 E2E 回归；记录模型、Prompt、数据和代码版本，异常时可以回退。
- **项目证据**：排产 30 条 Golden Cases、LLM-as-judge、Playwright E2E；Docker/Jenkins 用于构建和回归。
- **追问方向**：Prompt 变更算不算代码变更？
- **容易踩坑**：只测 HTTP 200，不验证业务结果。

### 30. 你如何设计一个企业级 RAG 服务？

- **参考回答**：分成文档接入、解析切片、Embedding、索引、检索、重排、上下文构建、生成、引用和评测层；补齐租户、权限、版本、删除、重建、监控和失败恢复。
- **项目证据**：Protocol AI 的切片、Embedding、pgvector、章节检索、引用追溯；面料项目的异步索引和权限。
- **追问方向**：文档更新和删除如何保证一致？
- **容易踩坑**：只设计一个向量表和一个查询接口。

### 31. 如何做 Agent 的人工接管？

- **参考回答**：在高风险、低置信或工具失败节点暂停，展示计划、证据和待执行参数，人工确认后继续；接管过程写入审计并可恢复。
- **项目证据**：BugleCat Approval、排产 dry-run 和治理链路。
- **追问方向**：人工确认后参数被修改怎么办？
- **容易踩坑**：人工确认只做一个“确定”按钮，没有展示上下文。

### 32. 你如何做权限和 Agent 安全的联动？

- **参考回答**：权限不只决定能不能打开页面，还决定模型能看到哪些数据、能调用哪些工具、工具能作用于哪些资源；每次工具调用重新校验，不能只依赖会话开始时的判断。
- **项目证据**：Noval Auth 的资源范围、面料 RBAC、排产四级权限。
- **追问方向**：角色变更后已有会话怎么办？
- **容易踩坑**：把 Agent 安全等同于 Prompt 安全。

### 33. Agent 线上性能下降如何排查？

- **参考回答**：先按 Trace 拆分模型、检索、数据库、外部工具和前端等待时间，找出首个真实瓶颈，再做索引、缓存、批量、并发或上下文优化，最后用同一批样本对比。
- **项目证据**：面料项目 N+1、图片尺寸、重复计算和 Redis 优化；Java 项目 SQL 从 3 秒到 500ms。
- **追问方向**：如何避免优化后准确率下降？
- **容易踩坑**：只看平均耗时，不看 P95、失败率和质量。

### 34. 如何选择 LangGraph、普通代码编排或工作流平台？

- **参考回答**：状态分支、循环、恢复和人工确认复杂时选择状态图；步骤固定时普通代码更简单；低代码平台适合快速验证和业务配置，但核心规则和安全边界仍要掌握在代码侧。
- **项目证据**：排产使用 LangGraph StateGraph；Lightweight AI Project Workflow 强调固定流程和验收门禁。
- **容易踩坑**：把框架选择说成个人偏好，没有结合任务复杂度。

### 35. Agent 系统如何支持多租户？

- **参考回答**：租户信息进入请求上下文和数据访问层，索引、缓存、日志、工具和审计都要带租户边界；模型上下文只允许读取当前租户授权内容。
- **项目证据**：企业 To B 系统中的数据范围、权限和审计经验。
- **待核验**：如果被问到实际多租户实现，需要补充具体项目和表结构证据。

## 技术负责人复试：交付、团队与取舍（36-50）

### 36. 你如何把一个 Agent 需求拆成开发任务？

- **参考回答**：按业务流程拆意图和验收，再拆数据、检索、工具、权限、前端、评测、部署和监控任务；每个任务都有输入、产出、依赖和完成条件。
- **项目证据**：To B 系统长期做需求沟通、数据模型、接口设计、任务拆解和上线验收。
- **追问方向**：怎么估工期？依赖变化怎么办？
- **容易踩坑**：只按页面或接口数量估算，忽略评测和数据准备。

### 37. 如何带 2-3 人团队完成 Agent 项目？

- **参考回答**：我负责目标、架构边界和关键风险，按成员能力拆分前端、数据、Agent 链路和测试；每日同步阻塞，关键代码做 Review，阶段性用可运行结果验收。
- **项目证据**：团队包含 1 名实习生和 1 名前端；排产和面料项目均有带队经历。
- **待核验**：补充一次具体的任务分配和成员成长案例。

### 38. 业务方要求“模型自己决定”，你怎么处理？

- **参考回答**：先把业务目标翻译成可验收的动作和风险等级，能确定性实现的部分由规则和服务负责，模型只承担适合它的理解和建议；通过演示和数据说明安全边界对交付的价值。
- **项目证据**：排产 Agent 的 LLM 限制在理解、解释和辅助决策。
- **容易踩坑**：直接拒绝业务方，没有给出可落地替代方案。

### 39. 如何做代码 Review？

- **参考回答**：先看正确性和边界，再看权限、幂等、失败恢复、可观测性和测试；Agent 代码重点检查工具副作用、Prompt/Schema 版本和模型失败路径。
- **项目证据**：长期负责 Review、联调、回归和交付验收；BugleCat 有工具和进程边界设计。
- **追问方向**：如何 Review AI 生成代码？
- **容易踩坑**：只看代码风格或让模型自己 Review 自己。

### 40. 项目延期时你如何推进？

- **参考回答**：先拆出关键路径和阻塞证据，区分必须交付和可延后能力，调整范围并保留质量门禁；每天同步风险，不用“快完成了”替代具体状态。
- **项目证据**：To B 项目中负责阶段推进、联调和验收。
- **待核验**：补充一次真实延期处理案例。

### 41. 如何决定 Agent 项目先做 Demo 还是直接做生产能力？

- **参考回答**：先做窄场景可验证 Demo，验证业务价值和数据质量；一旦进入真实数据或副作用链路，就补权限、审计、评测、监控和回滚，再谈生产。
- **项目证据**：Protocol AI 作为技术预研；排产 Agent 具备治理、评测和 E2E。
- **容易踩坑**：把 Demo 指标当生产指标。

### 42. 如何管理 Prompt、模型和知识库版本？

- **参考回答**：为 Prompt、模型、Embedding、切片规则和索引建立版本，运行记录绑定版本号；变更先跑固定样本，结果不达标不进入下一环境。
- **项目证据**：Golden Cases、Langfuse、引用追溯和 Agent 评测方法。
- **待核验**：当前项目具体版本字段和发布流程需要补充。

### 43. AI 项目的风险如何向管理层汇报？

- **参考回答**：按业务影响、发生概率、可检测性和回退成本说明风险，同时给出当前证据、缓解措施和上线条件，不只汇报模型效果。
- **项目证据**：Protocol AI 明确未上线边界；排产有权限、dry-run、verify 和审计。
- **容易踩坑**：用技术术语掩盖没有证据的结论。

### 44. 你如何在成本、效果和交付速度之间取舍？

- **参考回答**：先锁定不可妥协的安全和业务正确性，再在模型规模、检索深度、调用次数和功能范围上做取舍；通过小范围样本和阶段验收快速验证。
- **项目证据**：排产 SQL 优先降低 LLM 调用；面料通过 badcase 选模型；Protocol AI 聚焦框架优化。

### 45. 如何处理团队成员使用 AI 生成的大量代码？

- **参考回答**：要求提交上下文、设计意图和验证结果，Review 关注边界、错误处理、权限和可维护性；代码必须通过测试和运行验证，不能因为是 AI 生成就降低标准。
- **项目证据**：你长期使用 AI 辅助开发，同时保留人工 Review、Docker/Jenkins 回归和项目验收。

### 46. 讲一个你会主动承认边界的项目。

- **参考回答**：Protocol AI 就是一个例子。我会明确说自己负责 RAG 框架优化和技术预研，项目未上线生产；这样面试官能准确判断我的贡献，而不是被夸大的项目标签误导。
- **项目证据**：新风新研，2026-08-07 至 2026-09-04。
- **容易踩坑**：为了显得项目完整而补充未做过的医疗交付内容。

### 47. 你如何处理不同项目之间的技术复用？

- **参考回答**：复用稳定的方法和边界，例如 SQL 优先、混合检索、badcase、引用追溯和评测；先确认业务语义一致，再抽象组件，不能把一个项目的数据和结论直接搬到另一个项目。
- **项目证据**：排产和面料经验迁移到 Protocol AI 的 RAG 框架优化。

### 48. 你如何判断一个 Agent 组件是否可以平台化？

- **参考回答**：至少要有稳定输入输出、多个项目复用、明确验收、失败边界和安全约束；只出现一次的临时逻辑先留在项目内。
- **项目证据**：Lightweight AI Project Workflow 的 Skill 化标准和知识库沉淀方法。
- **容易踩坑**：为了平台化而过早抽象。

### 49. 你入职后前三个月会怎么推进 Agent 项目？

- **参考回答**：先理解业务和现有系统，梳理一个真实场景的输入、工具、数据和风险；选择窄场景做可验证闭环，再补评测、观测和权限，最后扩展到更多流程。
- **项目证据**：排产项目的确定性路由和阶段治理经验；Protocol AI 的框架优化方法。
- **容易踩坑**：一上来承诺搭建通用 Agent 平台或覆盖所有业务。

### 50. 你希望下一份工作重点负责什么？

- **参考回答**：希望负责 AI Agent 应用开发和工程化落地，把业务场景转成可控的 Agent、RAG 和工具链路，同时发挥 Java 后端、To B 交付和小团队推进经验。
- **项目证据**：当前简历定位和四个重点项目形成了这条技术主线。
- **追问方向**：更偏算法、平台还是业务应用？
- **容易踩坑**：只说想做 AI，没有说明能交付什么结果。
