# AI Agent 开发面试核心 30 题口语答案

使用方式：先记住“回答主线”，再用自己的语言补充细节。每题的“证据”来自当前已确认项目事实；标有“待核验”的内容，面试前必须补齐。

## 制造业排产 Agent

### 1. 这个项目解决了什么业务问题？为什么需要 Agent？

**回答主线**：生产人员需要用自然语言查询订单、机台和规格，并获得排产诊断。Agent 适合处理意图不固定、需要串联查询和解释的入口，但确定性业务规则仍由系统执行。

**项目证据**：项目覆盖订单查询、机台分析、规格推荐和排产诊断；基于真实订单抽象 20 类意图。

**取舍**：我没有让 LLM 直接决定或修改排产结果，而是让它负责理解、解释和辅助决策。

### 2. 你负责哪些部分，团队如何分工？

**回答主线**：我负责方案拆解、Agent 链路设计、关键模块开发、质量门禁和交付推进，同时带领 2-3 人小组。团队包含 1 名实习生和 1 名前端，我会按模块拆任务、做 Review、联调和验收。

**项目证据**：排产 Agent 中我的角色是技术负责人，简历确认团队规模为 2-3 人。

**待核验**：面试前补一版具体分工，例如谁负责前端、数据处理、评测或部署。

### 3. 排产 Agent 的整体架构和一次请求链路是什么？

**回答主线**：请求进入后先做意图识别，再根据意图选择 SQL、规则、向量检索或 LLM；需要编排时进入 LangGraph 状态图，涉及真实变更则经过权限、预览、执行、回读校验和审计。

**项目证据**：已确认链路为“请求理解 → 意图路由 → SQL/规则/检索 → Agent 编排 → dry-run → execute → verify”。

**追问准备**：能画出每个节点的输入、输出和失败分支。

### 4. 为什么 SQL 和规则优先，而不是所有问题都调用 LLM？

**回答主线**：订单、库存、机台负载等数据查询有明确结构，SQL 和规则在准确性、成本、延迟和可审计性上更稳定。LLM 只放在自然语言理解、复杂解释和辅助决策的位置。

**项目证据**：约 80% 请求无需调用 LLM，说明路由本身就是成本和稳定性优化。

### 5. 20 类意图如何抽象？95% 准确率如何得到？

**回答主线**：先按业务动作和所需数据把请求归并为意图，再为每类意图定义参数、路由和验证规则；用离线样本集评估分类结果，错误样本回流到 Golden Cases。

**项目证据**：20 类意图、离线准确率约 95%。

**待核验**：样本数量、训练或提示词方式、准确率计算口径必须按真实记录回答。

### 6. 如何防止 Agent 误改生产数据？

**回答主线**：把查询、建议和执行分开；执行前做权限校验、参数校验和 dry-run，执行后回读校验并写审计。工具默认最小权限，异常时 fail-closed。

**项目证据**：排产 Agent 使用 governance → preview/dry-run → execute → verify，配合四级权限、幂等和回读校验。

### 7. 如何设计工具参数校验、权限和幂等？

**回答主线**：工具定义明确输入 schema 和允许的数据范围，调用前校验身份、角色、资源和业务状态；写操作使用业务幂等键，重复请求返回已有结果或安全拒绝。

**项目证据**：已有四级权限、幂等、状态机和回读校验的设计。

### 8. Golden Cases、LLM-as-judge 和 Playwright E2E 如何配合？

**回答主线**：Golden Cases 验证固定输入输出和关键边界，LLM-as-judge 只作为辅助评价，Playwright E2E 验证真实页面和链路，最后结合日志人工复核。

**项目证据**：排产 Agent 已使用 30 条 Golden Cases、LLM-as-judge、Langfuse 和 Playwright E2E。

## Protocol AI / RAG

### 9. Protocol AI 是什么项目，你具体负责什么？

**回答主线**：它是新风新研的临床试验方案 AI 写作平台。我负责 RAG 框架和检索链路优化，包括文档切片、Embedding、pgvector、章节级检索、上下文构建和证据追溯。

**事实边界**：项目定位是 RAG 框架优化和技术预研，不是我从零独立交付的医疗生产系统。

### 10. 项目的准确时间和上线状态是什么？

**回答主线**：时间是 2026-08-07 至 2026-09-04，公司是新风新研；项目属于技术预研，未上线生产。

**注意**：这两个信息要直接回答，不用模糊的“最近参与过”。

### 11. 为什么不能说它是医疗生产系统？

**回答主线**：因为我的实际工作范围是框架优化和演示验证，不能把平台本身的业务目标等同于已完成生产交付。面试中我会明确说明上线边界，并只讲我亲自做过的检索和证据链路。

### 12. 排产 Agent 和面料检索经验如何迁移到 Protocol AI？

**回答主线**：排产项目提供 SQL 优先和多路由经验，面料项目提供向量与业务属性混合检索、badcase 评测经验；我把这些方法抽象到 Protocol AI 的章节检索、关键词兜底和上下文控制中。

**边界**：这是工程方法复用，不代表排产或面料数据已经接入医疗项目。

## 面料图像识别与检索

### 13. 面料项目的业务目标和你的职责是什么？

**回答主线**：目标是帮助研发和选样人员根据图片和业务属性查找相似面料。我负责项目方案、检索链路、性能和后台治理，并带领 2-3 人小组。

**项目证据**：项目包含图片采集、特征提取、向量检索、属性筛选、RBAC 和异步索引。

### 14. 图像向量和成分、组织、颜色等属性如何联合检索？

**回答主线**：先用图像向量召回视觉相似候选，再用成分、组织、颜色、纹理、克重等属性过滤或重排；这样既保留视觉相似，也符合业务筛选条件。

**取舍**：单一向量分数无法表达业务约束，所以需要混合检索和结果解释。

### 15. Qwen3-VL-Embedding-8B 如何验证和选型？

**回答主线**：使用真实样本和 badcase 做离线对比，关注相似结果、属性一致性、延迟和资源成本，再决定是否适合当前 GPU 和业务数据。

**项目证据**：已确认在 GPU 环境验证该模型，并用真实 badcase 对比选型。

**待核验**：具体对比模型、样本量和前后指标不要现场猜测。

### 16. 为什么不能只按向量相似度排序？

**回答主线**：视觉相似不等于业务可用，可能出现颜色接近但成分、组织或克重不符合的结果。因此需要属性过滤、重排和人工复核。

**项目证据**：系统明确组合图像向量与成分、组织、颜色、纹理、克重等属性。

## BugleCat / Coding Agent

### 17. BugleCat 和 nanocodex 是什么关系？

**回答主线**：它们是同一个个人 Coding Agent 项目，nanocodex 是早期名称，后来改名为 BugleCat，不能作为两个独立项目计算经历。

### 18. 为什么选择 Rust Core/CLI + Tauri/Svelte？

**回答主线**：Rust 负责核心状态、工具边界和本地执行安全，Tauri/Svelte 负责桌面界面和交互；这样能把高风险执行逻辑与 UI 解耦，也便于做 Worker、恢复和跨界面复用。

**项目证据**：项目已从 Python 原型重构为 Rust Core/CLI + Tauri/Svelte。

### 19. Agent Loop、Tool Calling 和 MCP 如何协作？

**回答主线**：Agent Loop 管理多轮状态和下一步决策，Tool Calling 把模型意图转成结构化工具请求，MCP 提供外部工具或资源的统一接入协议；工具执行结果再回到状态机。

**项目证据**：BugleCat 支持多轮 Agent Loop、Tool Calling、MCP、流式取消和持久化记忆。

### 20. Sandbox + Approval 如何控制副作用？

**回答主线**：工具先在受限沙箱中运行，涉及文件写入、命令执行或外部副作用时暂停并请求人工 Approval；审批记录和执行结果进入审计日志。

**项目证据**：已有 Sandbox、Approval、JSONL 审计和隔离 Worker 设计。

### 21. 如何验证本地 Coding Agent 的安全性和可回放性？

**回答主线**：验证工具 allow-list、沙箱边界、审批拒绝路径、超时取消、日志完整性和 checkpoint 恢复；用同一输入回放事件日志，确认结果和副作用可解释。

**项目证据**：BugleCat 包含 JSONL 审计、Checkpoint/Restore、Resume/Fork 和 A/B Worktree。

## 跨项目 Agent / RAG

### 22. 什么场景适合 Agent，什么场景普通工作流更合适？

**回答主线**：任务步骤固定、输入结构稳定、结果必须确定时优先普通工作流；任务需要自然语言理解、动态路由、工具选择和多步解释时才引入 Agent。Agent 增加了评测和治理成本，不能只因为用了大模型就采用。

**项目证据**：排产项目把 SQL 和规则优先，说明 Agent 只是链路中的一部分。

### 23. 如何设计一个可控的 Tool Calling 系统？

**回答主线**：工具要有明确 schema、最小权限、参数校验、超时和错误协议；调用前做权限与风险判断，写操作经过预览或人工确认，执行后回读并审计。

**项目证据**：排产 Agent 的 governance、dry-run、execute、verify，以及 BugleCat 的 ToolRegistry、Sandbox、Approval。

### 24. RAG 召回率、准确率和最终回答质量如何区分？

**回答主线**：召回率看相关证据是否被找回，准确率看召回内容是否相关，最终回答质量还要看是否基于证据、引用是否正确、是否满足任务约束。三者要分层评测，不能只看最终文本。

**项目证据**：Protocol AI 使用章节级检索、关键词兜底、引用追溯；面料项目使用真实 badcase。

### 25. 如何降低 Agent 成本和延迟？

**回答主线**：先用规则、SQL 和缓存解决确定性请求；缩小检索范围和上下文预算；只在必要节点调用模型；对重复 Embedding、图片处理和查询做缓存、批量化和异步化。

**项目证据**：排产 Agent 约 80% 请求不调用 LLM；面料项目加入 Redis 缓存、批量查询和异步索引。

### 26. 如何实现人工确认和 Fail-closed？

**回答主线**：高风险工具默认不执行，信息缺失、权限校验失败或依赖不可用时拒绝或暂停；人工确认要记录确认人、输入摘要、工具参数和结果。

**项目证据**：排产 Agent 有权限、dry-run、verify；BugleCat 有 Approval 和 Sandbox。

### 27. 如何做 Golden Cases 和回归测试？

**回答主线**：从真实请求、边界和历史 badcase 建立固定样本，覆盖正常、异常、权限和副作用路径；每次修改路由、Prompt、检索或工具后自动回归，再人工复核有争议样本。

**项目证据**：排产 Agent 已有 30 条 Golden Cases、LLM-as-judge 和 Playwright E2E。

## Java / 工程化

### 28. Spring Boot 和 MyBatis 在哪些真实项目中使用过？

**回答主线**：主要在浙江思维特的 CRM、金田 SRM、标准版 SRM，以及工路的支付微服务和 B2B 电商中使用 Spring Boot、MyBatis、MySQL、Redis；负责模块设计、接口、同步、性能和交付。

**项目证据**：金田 SRM 使用 Spring Boot + MyBatis，核心接口从 3 秒优化到 500ms；B2B 电商包含支付、履约和消息解耦。

### 29. Docker 镜像和容器部署中你负责哪些工作？

**回答主线**：我参与容器化交付，包括环境配置、镜像构建、服务启动、日志查看、依赖联调和发布回归；部分配置借助 AI 提高效率，但我会人工检查配置、执行结果和回滚路径。

**项目证据**：简历确认长期使用 Docker，多个 Java 和 Agent 项目列入 Docker 技术栈。

### 30. 如何拆解 To B 需求并推进交付？

**回答主线**：先确认业务目标和验收口径，再拆成数据模型、接口、权限、页面、任务和测试项；明确依赖和风险，按阶段联调、回归和验收，最后记录遗留项和上线边界。

**项目证据**：经历覆盖需求沟通、方案设计、任务拆解、代码 Review、联调测试、Docker/Jenkins 交付和上线验收。
