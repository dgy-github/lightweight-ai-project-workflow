## 3. 项目事实卡

### 3.1 制造业排产 Agent

- **公司与时间**：浙江思维特数字科技有限公司；2025-2026.04。
- **角色**：技术负责人，带领 2-3 人小组。
- **业务问题**：把生产订单查询、机台分析、规格推荐和排产诊断接入 Agent 工作流，同时保持核心业务动作可控、可追溯。
- **关键事实**：基于 49,981 条真实订单抽象 20 类意图；规则与 SQL 优先，约 80% 请求无需调用 LLM；离线意图识别准确率约 95%。
- **架构链路**：请求理解 → 意图路由 → SQL / 规则 / 检索策略 → Agent 编排 → 预览或 dry-run → 执行 → 回读校验 → 审计与评测。
- **工程决策**：LLM 主要负责理解、解释和辅助决策；关键动作由规则、权限和状态机约束。
- **质量与安全**：四级权限、幂等、回读校验、Langfuse、30 条 Golden Cases、LLM-as-judge、Playwright E2E。
- **技术栈**：Python、LangGraph、SQL、Qdrant、BGE/fastembed、Langfuse、Streamlit。
- **必须说清**：重点是 Agent 工程化和业务落地，不要把它描述成完全由 LLM 自主决策的黑盒系统。

可直接回答：

> 这个项目不是让大模型直接改排产数据，而是先做意图识别和路由。能用 SQL 或规则稳定解决的请求优先走确定性链路，只有需要解释或辅助决策的部分才调用 LLM；涉及真实变更时经过权限、预览、执行、回读校验和审计，保证可控和可回放。

### 3.2 Protocol AI｜临床方案生成 RAG 框架优化

- **公司与时间**：新风新研；2026-08-07 至 2026-09-04。
- **角色**：RAG 框架优化 / 技术预研。
- **上线边界**：未上线生产；不是从零独立交付的医疗生产系统。
- **项目目标**：在临床试验方案 AI 写作平台上优化知识检索与证据上下文链路。
- **关键链路**：文档切片 → Qwen Embedding → pgvector 检索 → 章节主题词增强 → 关键词兜底 → 上下文预算控制 → 章节级引用追溯。
- **证据治理**：保留来源角色、引用追溯和证据边界，避免把未选资料或模型常识误当成可验证医学结论。
- **能力复用**：复用了排产 Agent 的 SQL 优先和 Hybrid/Composite/GraphRAG 路由思路，以及面料项目的向量 + 业务属性混合检索和 badcase 评测方法。
- **技术栈**：FastAPI、Python、Qwen Embedding、pgvector、PostgreSQL、RAG。

必须使用的边界回答：

> Protocol AI 的真实定位是 RAG 框架优化和技术预研，时间是 2026-08-07 至 2026-09-04，未上线生产。我主要负责检索链路、上下文构建和证据边界优化，不把它包装成已经上线的医疗系统。

### 3.3 面料图像识别与检索系统

- **公司与时间**：浙江思维特数字科技有限公司；2025.10-2026.04。
- **角色**：项目负责人，带领 2-3 人小组。
- **业务问题**：为面料研发与选样提供图片采集、特征提取、向量检索和属性筛选能力。
- **数据事实**：1,522 个面料对象、4,236 张图片、约 14GB 图片数据；组合百度图像检索 API 与本地向量能力。
- **检索方法**：将图像向量相似度与成分、组织、颜色、纹理、克重等业务属性组合，并支持结果解释和人工复核。
- **模型与性能**：在 GPU 环境验证 Qwen3-VL-Embedding-8B；使用真实 badcase 对比选型；优化 N+1、图片尺寸和重复计算，加入 Redis 缓存、批量查询和重试。
- **工程治理**：RBAC、数据范围、Celery 定时任务和异步索引，使模型能力具备可运营、可追踪的后台支撑。
- **技术栈**：FastAPI、Python、SQLModel、PostgreSQL、Redis、Celery、百度图像检索 API、Qwen3-VL。

## 4. 跨项目可迁移能力

### 4.1 Agent 路由

不要默认所有请求都交给 LLM。先判断任务是否可以由 SQL、规则、确定性函数或已有状态直接完成，再决定是否需要 RAG、Tool Calling 或多 Agent。

### 4.2 RAG 质量

RAG 不是“接一个向量库”就结束。需要同时关注切片粒度、Embedding、召回策略、关键词兜底、重排或属性过滤、上下文预算、来源追溯和 badcase 评测。

### 4.3 副作用控制

凡是会修改数据、调用外部系统或产生费用的工具，都需要权限、参数校验、预览或 dry-run、幂等、超时、重试边界、回读校验和审计记录。

### 4.4 评测与可观测性

使用 Golden Cases、离线准确率、人工复核、LLM-as-judge、Langfuse、日志和 E2E 共同验证，不能只凭“模型回答看起来不错”判断效果。
